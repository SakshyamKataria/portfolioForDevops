# AWS S3 Artifact Storage

This project enforces S3 as the compulsory artifact store. Every successful build is zipped/synced to S3 before it is wrapped in a Docker container and deployed to Kubernetes.

## Bucket Structure

We use the bucket `sakshyam-portfolio-artifacts` in the `ap-south-1` region.

```text
s3://sakshyam-portfolio-artifacts/
└── releases/
    ├── 101/
    │   ├── build/            # The raw static files from 'npm run build'
    │   │   ├── index.html
    │   │   └── static/
    │   └── release.json      # Metadata: { buildNumber, gitSha, timestamp, branch }
    ├── 102/
    │   ├── build/
    │   └── release.json
    └── ...
```

## Why use S3 when we also use Docker?

It might seem redundant to store static files in S3 if we are also building Docker images, but this serves several critical architectural purposes:
1. **Audit Trail**: S3 acts as an immutable ledger of every release, perfectly stamped with its Git SHA and build time.
2. **Rollback Source**: If the k3s cluster crashes entirely and the local container registry is lost, we can instantaneously rebuild the exact Docker image for any past version directly from the S3 static archive.
3. **Faculty Story**: It demonstrates a decoupled pipeline. The CI/CD process breaks the build (React compile) apart from the deployment packaging (Docker).

## IAM Permissions (EC2 Instance Profile)

To adhere to the principle of least privilege, Jenkins (running on the EC2 instance) uses an IAM Instance Profile. No hardcoded AWS credentials (Access Keys) are stored in the repository.

Here is the minimum IAM policy required:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:PutObject",
                "s3:GetObject",
                "s3:ListBucket",
                "s3:DeleteObject"
            ],
            "Resource": [
                "arn:aws:s3:::sakshyam-portfolio-artifacts",
                "arn:aws:s3:::sakshyam-portfolio-artifacts/*"
            ]
        }
    ]
}
```

## Manual CLI Examples

If you need to interact with the artifacts manually (e.g., from your local machine with `aws-cli` authenticated):

### Uploading a build manually
1. Run `npm run build`
2. Run the provided script:
```bash
./scripts/s3-upload-artifacts.sh <BUILD_NUMBER> <GIT_SHA> <BRANCH>
```

### Listing stored releases
```bash
./scripts/s3-list-releases.sh
```

### Downloading a specific release for debugging
```bash
aws s3 sync s3://sakshyam-portfolio-artifacts/releases/101/build/ ./local-debug-folder/
cat ./local-debug-folder/release.json
```
